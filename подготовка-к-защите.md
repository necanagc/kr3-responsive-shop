# Подготовка к защите проекта «МузТорг Жуковский»

## Коротко о проекте

Это адаптивный многостраничный сайт магазина музыкального оборудования. В проект входят главная страница, каталог, страница товара, форма заявки и контакты. Основные технологии — HTML, CSS и JavaScript.

При разработке важно было сохранить читаемость и удобство страниц на узких и широких экранах, а также обеспечить доступность навигации и элементов управления.

## Главная тема защиты: позиционирование

В CSS позиционирование отвечает за то, как элемент располагается относительно обычного потока документа, окна браузера или другого элемента. В проекте применяются `sticky`, `fixed` и `absolute`. Большую часть компоновки при этом делают не свойства `position`, а Flexbox и CSS Grid.

### `position: sticky` — шапка сайта

В [responsive.css](./css/responsive.css) для `.site-header` заданы:

```css
.site-header {
  position: sticky;
  top: 0;
  z-index: 100;
}
```

Шапка участвует в обычном потоке страницы, но при прокрутке прилипает к верхнему краю окна. `top: 0` задаёт место прилипания, а `z-index: 100` помогает шапке оставаться над основным содержимым.

**Почему не `fixed`:** фиксированная шапка всё время находилась бы поверх страницы и была бы исключена из обычного потока. `sticky` сохраняет место шапки в разметке и закрепляет её только при прокрутке.

### `position: fixed` — кнопка «Наверх»

В [style.css](./css/style.css) элемент `.scroll-top` закреплён у правого нижнего края окна:

```css
.scroll-top {
  position: fixed;
  right: var(--space-lg);
  bottom: var(--space-lg);
  z-index: 5;
}
```

В [responsive.css](./css/responsive.css) отступы меняются на узких и широких экранах. Кнопка остаётся в одном месте окна при прокрутке и не занимает место в потоке страницы. Её ссылка ведёт к элементу `id="top"` в шапке.

**Почему здесь подходит `fixed`:** кнопку полезно держать доступной в одном и том же месте независимо от длины страницы и текущей прокрутки.

### `position: absolute` — ссылка пропуска и скрытый заголовок

В [style.css](./css/style.css) ссылка `.skip-link` изначально вынесена за верхнюю границу видимой области:

```css
.skip-link {
  position: absolute;
  top: -100px;
  left: 16px;
  z-index: 1000;
}

.skip-link:focus,
.skip-link:focus-visible {
  top: 16px;
}
```

Так ссылка не мешает обычному просмотру страницы, но появляется, когда пользователь переходит по странице клавиатурой и фокус попадает на неё. По ссылке можно перейти прямо к основному содержимому. Большое значение `z-index` позволяет ей отображаться поверх других элементов.

Класс `.visually-hidden` также использует `position: absolute`, чтобы скрыть заголовок визуально, не убирая его из структуры страницы и дерева доступности.

### Как различать основные значения `position`

| Значение | Как ведёт себя | Пример в проекте |
|---|---|---|
| `static` | Значение по умолчанию: элемент располагается в обычном потоке; координаты `top`, `left` и подобные не задают его положение | Большинство элементов |
| `relative` | Элемент остаётся в потоке, но его можно сдвинуть относительно исходного места; также часто служит опорой для абсолютных потомков | В проекте сейчас явно не используется |
| `absolute` | Элемент исключается из потока и позиционируется относительно ближайшего предка с позиционированием; если такого предка нет — относительно начального содержащего блока | `.skip-link`, `.visually-hidden` |
| `fixed` | Элемент закрепляется относительно окна браузера и не перемещается вместе с обычным содержимым страницы | `.scroll-top` |
| `sticky` | Сначала элемент ведёт себя как обычный, затем прилипает к заданному краю при прокрутке | `.site-header` |

`z-index` управляет порядком наложения элементов, когда это применимо. Он не заменяет позиционирование и сам по себе не задаёт координаты.

## Позиционирование и адаптивная компоновка — не одно и то же

На защите полезно подчеркнуть, что расположение большинства блоков здесь сделано средствами Flexbox и Grid, а не абсолютными координатами:

- Шапка использует Flexbox: логотип и навигация располагаются в строке или переносятся.
- Карточки выстраиваются в CSS Grid. В [responsive.css](./css/responsive.css) число колонок меняется по ширине: одна колонка на узком экране, две от `640px`, три от `1024px` и четыре от `1280px`.
- Фильтр и товары каталога располагаются областями CSS Grid: на мобильном фильтр стоит над товарами, начиная с `768px` — слева от них.
- Страница товара использует Grid: на планшетном размере элементы складываются, а от `1024px` изображение и описание располагаются рядом.
- Форма заявки переходит с одной колонки на две от `768px`.

Grid и Flexbox управляют компоновкой в потоке. Это обычно устойчивее, чем задавать каждому блоку координаты через `top` и `left`: содержимое может переноситься, а сетка — перестраиваться на другом экране.

## Другие адаптивные решения

- Подход Mobile First: базовые правила рассчитаны на узкий экран, а медиазапросы добавляют более широкую компоновку.
- Hero выбирает разные изображения через `<picture>` и `media`.
- Для изображения товара используются `srcset` и `sizes`, чтобы браузер мог подобрать подходящий файл.
- У изображений задана максимальная ширина, а таблица характеристик при необходимости прокручивается внутри собственного контейнера.
- Отступы кнопки «Наверх» адаптируются под ширину экрана.

## Доступность и проверка

- На страницах есть ссылка пропуска к основному содержимому и основной заголовок.
- У полей форм есть подписи, изображениям заданы альтернативные описания.
- Видимый фокус помогает понять, какой элемент выбран при навигации с клавиатуры.
- Учитывается настройка пользователя `prefers-reduced-motion`.
- Lighthouse Accessibility показал **100/100** для главной, каталога, страницы заявки и страницы товара. HTML-отчёты сохранены в папке [lighthouse/](./lighthouse/).

Папка `lighthouse/` содержит результаты проверок, а не файлы, необходимые для работы страниц. Её стоит оставить, если отчёты нужны как подтверждение проверки или включены в сдаваемые материалы; если преподаватель просит сдать только исходники сайта, папку можно не включать в архив.

## Возможные вопросы и короткие ответы

**Почему шапка не `fixed`?**  
`sticky` оставляет её место в потоке и закрепляет только при прокрутке до верхней границы. `fixed` постоянно висел бы поверх содержимого.

**Почему кнопка «Наверх» `fixed`?**  
Она должна оставаться доступной у края окна, пока пользователь прокручивает длинную страницу.

**Зачем ссылке пропуска `absolute`?**  
Чтобы убрать её из обычного визуального расположения, но показывать при получении фокуса с клавиатуры. Так пользователь может пропустить повторяющуюся навигацию и перейти к основному содержимому.

**Зачем нужен `z-index`?**  
Он задаёт порядок отображения перекрывающихся элементов. Например, шапка должна быть поверх содержимого, а ссылка пропуска — поверх шапки и страницы.

**Почему не размещать все блоки через `absolute`?**  
Абсолютные координаты не перестраивают страницу при изменении ширины и объёма текста; элементы могут перекрываться. Flexbox и Grid лучше подходят для адаптивной компоновки.

**Как проверить адаптивность?**  
Изменить ширину окна или использовать режим устройства в инструментах разработчика, проверить переносы и прокрутку, а также посмотреть, как медиазапросы перестраивают сетки.

## Краткий ответ для устной защиты

> В проекте есть три осмысленных вида позиционирования. `sticky` закрепляет шапку у верхнего края при прокрутке, `fixed` держит кнопку «Наверх» в углу окна, а `absolute` используется для ссылки пропуска, которая появляется при клавиатурном фокусе, и для визуально скрытого заголовка. Основные сетки сделаны не абсолютным позиционированием, а Flexbox и CSS Grid: поэтому карточки, каталог, форма и страница товара могут перестраиваться под ширину экрана.
